# DeepSeek Bot 开源项目调研

核查日期：2026-10-31（Asia/Shanghai）。

范围更新：用户随后明确服务器浏览器也属于第一版核心目标。新增的官方 Grok Bot 机制、现有 Chrome 检查、OpenClaw 与浏览器执行工具候选见 [Grok Bot机制与项目方案](./Grok%20Bot机制与项目方案.md)。下文保留首轮聊天、记忆与调度组件调研；完整系统基础的选型，以更新方案中的 Agent 运行时与浏览器验证为准。

本轮工作：读取官方仓库、许可证、默认分支提交、部署文件和关键源码。没有安装、启动这些项目，没有修改云服务器，也没有把第三方业务代码复制进本项目。下面的资源适配判断来自静态分析，尚非运行测试结论。

## 项目需求与判断标准

已确认的需求：个人自用，DeepSeek 驱动；电脑与安卓使用；多个具有性格和记忆的 Bot；主动联系、定时提醒；多个 Bot 群聊。随后明确第一版要能操作服务器浏览器，不控制用户本机。界面参考用户提供的联系人列表与聊天截图，不据截图中的模型自述判断 Grok 的内部实现。

上一轮 SSH 盘点：上海的 Ubuntu 22.04 服务器，2 核、约 2 GB 内存，已有 Nginx 和其他服务。模型采用远程 API；正式选型仍需测量实际常驻内存、磁盘、后台执行与安卓送达情况。

重点判断四件事：

1. 角色、记忆、群聊和主动消息是已经实现，还是插件、托管服务或规划。
2. 自动发言发生在浏览器里，还是由独立运行的服务器触发。
3. 任务和消息是否保存，重启后是否恢复，失败是否可追踪。
4. 能否只选择需要的模块，以及对应源码的许可证是什么。

## 结论

- **多角色与群聊：优先研究 SillyTavern，补充参考 RisuAI。** 两者已有角色与上下文处理，适合实际体验后再决定是否改造现成底座。
- **服务器提醒：优先研究 AstrBot。** 有持久化任务和启动恢复，但一次性任务的失败处理策略需要按本项目要求重新设计。
- **主动联系：研究 Shikigami-Protocol。** 冷却、次数限制、未回复时停止等规则很有参考价值；其内存计时器不适合作为可靠提醒的最终实现。
- **完整网站底座：保留 Open WebUI 作为重点候选。** 已有角色预设、频道、服务器定时、用户记忆和 PWA；需要验证角色私有记忆、联系人界面和手机通知。
- **记忆组件：保留 Mem0 Python 库作为可选依赖。** 先确认中文效果、额外 embedding 服务和隔离规则，再决定是否引入。

首轮建议的 SillyTavern 与 Open WebUI 对比，现作为角色与聊天体验参考。新增云浏览器目标后，下一阶段应优先比较完整 Agent 运行时与轻量自建运行时，贯通 DeepSeek → 浏览器动作 → 任务状态和真实结果，再确定基础与界面。当前不锁定最终技术栈。

### SillyTavern：角色与群聊

采用 `release` 分支快照。DeepSeek 是内置提供方；摘要功能是随仓库提供的扩展，不应笼统当作所有记忆能力都默认启用。

重点代码入口：

- [group-chats.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/public/scripts/group-chats.js#L945)：`generateGroupWrapper()` 负责角色发言选择和生成。适合研究自然、列表、手动等发言策略。
- [自动群聊计时器](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/public/scripts/group-chats.js#L144)：运行于浏览器的 `setInterval()`，不能当作关闭网页后的服务器提醒。
- [DeepSeek 后端](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/src/endpoints/backends/chat-completions.js#L1071)：服务器端请求与密钥读取。模型名和 API 参数应按接入时的 DeepSeek 文档重新核实。
- [摘要扩展](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/public/scripts/extensions/memory/index.js#L93)：研究摘要何时更新、如何注入请求；选用 Extras 等模式可能需要额外服务。

适配判断：先直接体验的价值高。改成截图那样的简洁界面，会涉及较多设置与前端逻辑的取舍。手机通过浏览器访问服务器可参考[官方 FAQ](https://docs.sillytavern.app/usage/faq/)。

### RisuAI：跨端界面与上下文压缩

源码已有 Svelte/TypeScript 网页与 Tauri 桌面工程；主流程实际包含群聊、记忆和 DeepSeek 接入。

- [聊天与群聊主流程](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/src/ts/process/index.svelte.ts#L295)：筛选成员、排序、依次生成；同一文件包含记忆调用。
- [HypaMemoryV3](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/src/ts/process/memory/hypav3.ts#L122)：摘要、重要记忆、相似片段与上下文预算。
- [存储选择](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/src/ts/storage/autoStorage.ts#L173)：不同环境采用账户、Node、OPFS 或浏览器本地存储。静态托管本身不代表已经跨设备同步。
- [浏览器通知](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/src/ts/process/index.svelte.ts#L1947)：生成结果后的 `new Notification()`，不能据此证明离线推送。

当前 [Hono 服务说明](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/server/hono/README.md)标记开发中；自托管选型需要同时看 [Node 服务说明](https://github.com/kwaroran/Risuai/blob/ea61945f9038e0189807d075f55f4e66ab7e98bf/server/node/readme.md)。

### AstrBot：任务后台

其 [future_task 官方说明](https://github.com/AstrBotDevs/AstrBot/blob/3d92821ad9d90df33fc242e7b159a3260075eb2c/docs/zh/use/proactive-agent.md)仍标为实验性。它的 QQ 等平台群消息支持，与多个 AI 人格在同一房间讨论是不同能力。

- [cron_tools.py](https://github.com/AstrBotDevs/AstrBot/blob/3d92821ad9d90df33fc242e7b159a3260075eb2c/astrbot/core/tools/cron_tools.py)：创建、查询、修改、删除任务的模型工具接口和所属会话检查。
- [cron/manager.py](https://github.com/AstrBotDevs/AstrBot/blob/3d92821ad9d90df33fc242e7b159a3260075eb2c/astrbot/core/cron/manager.py)：数据库保存、启动恢复、APScheduler 调度与任务状态。
- [cron/events.py](https://github.com/AstrBotDevs/AstrBot/blob/3d92821ad9d90df33fc242e7b159a3260075eb2c/astrbot/core/cron/events.py)：把到时触发接回正常 Agent 流程和原消息会话。

关键边界：文档说明一次性任务触发后，无论成功或失败都会删除；不能假定停机错过的任务全部补发。本项目应单独保留任务定义、执行历史和失败状态，定义重试与过期规则。

当前 Python 要求为 ≥3.12，服务器系统 Python 3.10 不满足；容器可隔离运行环境。远程模型 API、少量插件的方式值得验证，当前没有 2 GB 机器上的资源实测。

### Shikigami-Protocol：主动性与角色记忆

与产品设想相近，但项目较新，不能仅依据功能清单认定稳定可用。

- [ase.py](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/core/ase.py)：主动发言阈值、静默时间、冷却、24 小时次数上限和用户未回应时的限制。
- [reflection.py](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/core/reflection.py)：后台反思与主动意愿更新。它与 ASE 当前只检查活跃角色，不能当作所有联系人同时持续活动。
- [memory_manager.py](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/memory/memory_manager.py)：按角色组织事实、日摘要与可选向量记忆。
- [groups.py](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/api/groups.py)：群成员发言顺序与 `max_replies_per_turn` 限制。

提醒部分的 [TimerManager](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/tools/timer/manager.py)使用内存字典与线程，缺少持久化恢复。[broadcast.py](https://github.com/Shikigami-Lab/Shikigami-Protocol/blob/b0fe0a2b97abe28cff6c8cffa8184a614a1cafd3/src/core/broadcast.py)面向已连接的 SSE 客户端，不能证明手机锁屏通知。

存在 server-only 运行方式；关闭本地语音和可选向量、调用云端模型，方向上更符合当前机器。后台反思会增加 API 调用次数，应先设预算与上限。

### Open WebUI：完整网站底座候选

[当前 README](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/README.md)列出模型预设、频道、长期记忆、日历、Automations 和 PWA。下面几项已进一步查到对应源码：

- [utils/automations.py](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/open_webui/utils/automations.py#L70)：后台轮询到期任务；使用聊天生成管线、保存结果和记录成功失败，也支持向频道发送。
- [models/automations.py](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/open_webui/models/automations.py#L298)：任务数据与到期任务领取逻辑。正式复用还需测试崩溃窗口、过期和重试行为，不能仅凭有数据库就承诺永不漏发。
- [routers/channels.py](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/open_webui/routers/channels.py#L1244)：处理频道中被 @ 的模型；不是已经验证的自主多 Bot 群聊主持系统。
- [models/memories.py](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/open_webui/models/memories.py#L15)：记忆主要以 `user_id` 归属；`path` 可组织内容，但不等于强制的 Bot 私有范围。角色隔离仍需设计和验证。
- [utils/notifications.py](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/open_webui/utils/notifications.py#L29)：所查通知目标是 webhook。存在通知出口不等于安卓已经收到系统通知。

部署方面，[Dockerfile](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/Dockerfile#L139)有 `USE_SLIM` 分支，避免打包本地模型和部分音频/文档工具；[slim 依赖](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/backend/requirements-slim.txt)支持 SQLite 与外部 AI 服务。比启用本地模型的配置更适合列入 2 GB 机器试运行候选，但没有实测数据。

许可并非简单的 MIT/Apache：[Open WebUI License](https://github.com/open-webui/open-webui/blob/f7ac7ee10962ddec0017f5c29b6740d9b9c5faca/LICENSE)含品牌保留条款，同时对任意滚动 30 天内不超过 50 个终端用户的部署/分发列有例外。当前个人自用与该例外相关；如果以后扩大用户范围，需要重新按当时条款评估，不能把整库统一改成自有许可证。

### Mem0：可选记忆依赖

- [memory/main.py](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/mem0/memory/main.py)：提取、检索、编辑、删除、历史；有 `user_id`、`agent_id`、`run_id` 等筛选。当前 V3 自动提取采用 ADD-only 管线，不能沿用旧教程假定会自动更新或删除冲突事实。
- [llms/deepseek.py](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/mem0/llms/deepseek.py)：内置 DeepSeek 提供方，但源码默认模型名仍需在接入时显式核实。
- [vector_stores/qdrant.py](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/mem0/vector_stores/qdrant.py)和[配置](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/mem0/configs/vector_stores/qdrant.py)：支持进程内路径模式；默认 `/tmp/qdrant` 必须换成稳定数据目录。历史记录另有 SQLite 存储。
- [server/docker-compose.yaml](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/server/docker-compose.yaml)：完整服务栈包含 API、PostgreSQL/pgvector 与 dashboard，和嵌入 Python 库的开销不同。

默认 LLM 与 embedding 均使用 OpenAI。仅把 LLM 改成 DeepSeek，仍需另外配置 embedding 模型或 API。筛选标识也不是现成的共享/私有权限系统，后台必须强制检索范围，避免只按用户查询而混入其他角色记忆。

第一版可以先实现可编辑的共享资料、Bot 私有事实、对话摘要；将 Mem0 留作可替换记忆适配器。是否引入，由中文提取效果、冲突纠正、删除与隔离测试决定。

## 后续复用与验证清单

每个实际引入的依赖或源码片段记录上游仓库、锁定版本、文件路径、修改范围与许可证；完整应用、可独立安装的库、参考后自行实现的规则分别记录。实际复制或分发时按对应文件的许可处理。当前仅保存调研记录，未决定复制代码。

优先验证以下同一组使用场景：

1. 创建三个性格明显不同的 Bot，电脑发送后手机能看到同一份记录。
2. 各 Bot 记住自己的聊天事实；修改或删除记忆后，不再通过旧摘要或检索结果重新带回。
3. 群聊支持指定角色与停止，达到轮次上限后确实停止调用模型。
4. 创建提醒后关闭网页，后台仍执行；重启服务后能恢复待执行任务。
5. 模型请求失败、网络断开或服务器停机时，任务状态清楚，重试不重复投递；过期是否补发有明确规则。
6. 主动联系遵守静默时段和频率上限；用户不回复时会停止继续打扰。
7. 分别记录“任务已执行、消息已保存、通知已提交、手机是否实际显示”，进行安卓前台、后台、锁屏与实际网络验证。
8. 在现有服务器上测常驻内存、响应延迟与磁盘增长，再确认常驻部署配置。

只有这些验证完成后，才能将候选项目的能力认定为本项目可用能力。
