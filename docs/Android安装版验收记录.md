# Android 安装版验收记录

日期：2026-10-31。版本1.0.0，包名 `io.github.upinking.deepseekbot`，最低 Android 8.0/API26，目标 API36。正式 APK 约28KB，使用私人 RSA3072 密钥签名；密钥、密码、预置服务器地址和 APK 不提交公共源码仓库。

## 已实际完成

| 项目 | 实际证据与结论 |
|---|---|
| 正式构建与签名 | `scripts/build_android.py --offline` 生成正式安装包；`apksigner verify` 成功，v2签名有效。Manifest 仅有 INTERNET 权限，正式包无 DEBUGGABLE 标志，BuildConfig.DEBUG=false。 |
| 静态与边界检查 | Android Lint：0错误，1条启用JavaScript的提示（当前界面需要JavaScript，未开放JS原生桥接）。46项URL边界、22项文件名解析检查通过。Android 8.0与8.1导航栏样式分别提供；旧版返回回调仅作为API26–32后备，新系统使用Dispatcher。 |
| 实际安装 | 在 ARM64 Android16/API36 模拟器安装正式 APK 并启动，加载私有 HTTPS 工作台，原生工具栏、登录页和手机聊天界面实际显示。系统 WebView 版本133.0.6943.137。 |
| 登录与重启 | 使用现有工作台密码登录；后台暂停、强制停止进程再启动后无需重新登录，私有设置API实际返回200。覆盖安装更新后会话仍保留。 |
| 真实聊天 | 临时验收 Bot 收到安装版发送的消息，服务器调用真实 DeepSeek，安装版显示“安卓安装验证成功”。此项没有使用模拟模型回答。 |
| SAF上传 | 打开系统文件选择器，取消后再次选择 Downloads 中的中文UTF-8附件；界面成功挂载附件。服务端下载核对为71字节，与原文件逐字节相同。确认 `setAllowContentAccess(false)` 没有阻止用户明确选择的 `content://` 附件上传。 |
| SAF下载 | 点击聊天附件，系统选择保存位置；通过原生HTTPS请求携带当前登录Cookie下载。实际保存后读取文件为71字节，内容完全一致。修复通用二进制MIME造成 `.txt` 改为 `.bin` 的问题后，保存器默认名称保留为 `android-upload.txt`，再次保存及核对通过。 |
| 键盘与返回 | 软键盘展开后WebView可用高度从792变为480 CSS像素，发送按钮仍在可视范围；系统返回隐藏键盘，恢复792高度，工作台仍位于前台。 |
| 外链 | 实际点击 `target=_blank` 的外部链接，系统Chrome进入前台；工作台保持独立。URL策略额外覆盖不同域、端口、路径边界、账号嵌入、危险协议和多次编码穿越。 |
| 证书错误 | 将测试地址切换到本机自签名HTTPS服务，安装版明确显示安全连接失败，没有加载不可信内容或提供忽略证书继续按钮；恢复原地址后可以继续使用。 |
| 交付下载 | 将最终正式APK上传工作台私人文件区，再通过认证下载并比对SHA-256，确认线上文件与本地安装包完全一致。 |

模拟器系统为userdebug版本，其WebView可由系统强制开放开发调试；测试通过本机ADB转发的CDP观察真实WebView。正式构建本身明确关闭应用和WebView调试，不把模拟器系统策略当作普通用户手机的行为。[Chromium源码说明](https://chromium.googlesource.com/chromium/src/+/3546854f59..2e285ebae2)

本地证据放在被忽略的 `output/qa/android-*`，包括正式构建日志、原始及下载附件、登录/聊天/键盘/证书错误截图。临时 Bot 和测试附件在验收后清理；正式APK保留在私人工作台文件区，便于手机浏览器下载。

## 范围与未验收项

这是一款复用云端工作台界面的 Android 客户端，支持原生返回、服务器设置、文件选择与保存。APK 不包含 DeepSeek 密钥，不在手机离线运行模型。

没有连接用户的实体手机，因此厂商系统安装流程、具体机型输入法和省电策略没有标记为通过。Android锁屏推送尚未接入；服务器仍执行提醒与后台任务，重新打开应用可读取结果。
