# 消息定位与音乐律动

## 消息定位

聊天区左边每条短线对应一条消息。浅灰线标识历史消息，深色线标识阅读位置。悬停或键盘聚焦后会显示作者、时间、消息序号及摘要；点击跳转，手机直接点短线。长对话的定位条可独立滚动，不会省略中间消息。

键盘：Tab 进入当前定位点，方向键或 Home/End 选择，Enter/空格跳转，Escape 关闭预览。定位不会发送消息、调用模型或改动聊天内容。会话切换、空会话和加载失败时会清理原来的定位目标。

## 跟随电脑中其他软件的音乐

1. 在电脑上通过 HTTPS 打开工作台，点聊天右上角的音符。
2. 点“连接电脑音频”。浏览器会打开系统共享选择器。
3. 选择音乐窗口或屏幕，并勾选“共享音频”。其他软件继续负责播放音乐。
4. 有声音时横条长度随真实频谱变化；静音时不制造随机跳动。消息预览和跳转继续可用。
5. “暂停律动”只暂停动画，音频共享仍保持；“断开音频”会结束本次共享。隐藏面板时共享保持，右上角音符保持连接提示，可重新打开管理。

刷新、退出登录或结束系统共享会断开连接，下次需要重新选择来源。系统设置为减少动态效果时保留静态定位。页面在后台时停止更新动画。

## 来源与隐私

这是电脑浏览器功能，不能从云服务器读取本机声音。浏览器的 `getDisplayMedia` 要求同时申请画面轨道，因此弹窗可能称为共享屏幕或窗口；程序保留画面轨道以维持共享会话，不展示、录制或上传它。声音只由当前页面的 Web Audio 分析，既不录音，也不发给服务器或模型，不再次播放，避免产生重音。程序不请求麦克风。

来源选择和音频支持取决于浏览器、操作系统及系统权限。没有音轨时会立即释放所有轨道，并提示重新选择或当前环境不支持；拒绝或取消后可重试。手机和当前 Android WebView 客户端不支持抓取其他 App 的声音，但继续支持消息定位，不要求安装额外录音组件。

依据：[Chrome 屏幕共享控制](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)、[W3C 屏幕捕获规范](https://w3c.github.io/mediacapture-screen-share/)、[Web Audio 规范](https://www.w3.org/TR/webaudio/)。`systemAudio: include` 是浏览器选项提示，不保证每个环境都返回音轨。

## 实现与验证范围

- `web/chat-rail.js` 独立维护导航、预览和阅读位置，聊天轮询不替换它的外壳。`ResizeObserver` 处理内容高度及窗口变化。
- `web/music-player.js` 通过 `MediaStreamAudioSourceNode → AnalyserNode → 静音 GainNode → destination` 读取 32 段频谱，不回放共享的声音。所有异步连接都有代次检查，断开后迟到的授权结果会立即释放。
- Node 回归覆盖静音与频谱、暂停、无音轨、拒绝重试、连接期间取消、共享结束、关闭 AudioContext、释放全部音视频轨道及不支持环境提示。
- 浏览器验收覆盖桌面与 393×852/393×568 视口、48 条和 160 条历史、键盘、预览、跳转、切换及空会话；共享连接和断开已在应用内浏览器操作验证。当前未验证用户日常浏览器选择的具体外部播放器能否提供非静音音轨，需在那台设备选择实际来源后确认；不能把模拟频谱测试当成该硬件验证。
